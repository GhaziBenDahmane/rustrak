# Installation

Rustrak is one container. It ingests events, answers the API and serves the
dashboard, all on port `8080`. There is nothing to configure for the
dashboard.

## Docker

The default image stores everything in SQLite, so no database has to run next
to it:

```bash
docker run -d \
  --name rustrak \
  -p 8080:8080 \
  -v rustrak_data:/data \
  -e SESSION_SECRET_KEY=$(openssl rand -hex 32) \
  -e CREATE_SUPERUSER=admin@example.com:changeme123 \
  -e PUBLIC_URL=http://localhost:8080 \
  rustrak/rustrak-server:latest
```

Open **http://localhost:8080** and sign in with the credentials from
`CREATE_SUPERUSER`. The sign-in page is `/login`.

- **`rustrak_data`** holds the database and uploaded source maps. Keep it, and
  the data survives restarts and upgrades
- **`SESSION_SECRET_KEY`** signs the session cookie. Keep the same value across
  restarts, or everyone is signed out
- **`PUBLIC_URL`** is the address your SDKs send events to and the host
  written into every DSN. Set it to your public address in production

SQLite suits personal projects, small teams and up to about 1,000 events an
hour. For more, use [PostgreSQL](#postgresql).

## Docker Compose

The same setup as a Compose file. This is the `docker-compose.yml` at the root
of the repository:

```yaml
services:
  server:
    image: rustrak/rustrak-server:latest
    ports:
      - "8080:8080"
    environment:
      - SESSION_SECRET_KEY=${SESSION_SECRET_KEY}
      - CREATE_SUPERUSER=${CREATE_SUPERUSER}
      - PUBLIC_URL=${PUBLIC_URL:-http://localhost:8080}
    volumes:
      - rustrak_data:/data
    restart: unless-stopped

volumes:
  rustrak_data:
```

With a `.env` next to it:

```bash
# openssl rand -hex 32. The server refuses to start without a valid one.
SESSION_SECRET_KEY=
# email:password. Only used when no user exists yet.
CREATE_SUPERUSER=admin@example.com:changeme123
# The address SDKs reach, e.g. https://rustrak.example.com
PUBLIC_URL=http://localhost:8080
```

```bash
docker compose up -d
```

> **Reverse proxy?** Behind Traefik, nginx or Caddy, delete the `ports` block
> and let the proxy reach the container on `8080`. Set `PUBLIC_URL` to your
> public host. See [Reverse proxy](/configuration/production#reverse-proxy).

## PostgreSQL

For higher volume or concurrent writes, use the `postgres` image and a
PostgreSQL database. The repository ships this as `docker-compose.postgres.yml`:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: rustrak
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: rustrak
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U rustrak -d rustrak"]
      interval: 5s
      timeout: 5s
      retries: 5
    restart: unless-stopped

  server:
    image: rustrak/rustrak-server:postgres
    ports:
      - "8080:8080"
    environment:
      - DATABASE_URL=postgres://rustrak:${POSTGRES_PASSWORD}@postgres:5432/rustrak
      - SESSION_SECRET_KEY=${SESSION_SECRET_KEY}
      - CREATE_SUPERUSER=${CREATE_SUPERUSER}
      - PUBLIC_URL=${PUBLIC_URL:-http://localhost:8080}
    volumes:
      # Uploaded source maps. The database lives in PostgreSQL.
      - rustrak_data:/data
    depends_on:
      postgres:
        condition: service_healthy
    restart: unless-stopped

volumes:
  postgres_data:
  rustrak_data:
```

Add `POSTGRES_PASSWORD` to the `.env` above and run
`docker compose -f docker-compose.postgres.yml up -d`. To use a database you
already run, drop the `postgres` service and point `DATABASE_URL` at it. See
[Database backends](/configuration/database).

## The dashboard

It is compiled into the image and served from `/`, on the same origin as the
API, so there is no second container and no address to configure. The whole
image, dashboard included, is about 20 MB, and the server idles under 100 MB
of memory.

Two cases need something extra:

- **No dashboard at all.** Set `RUSTRAK_DASHBOARD=off` and the server answers
  the API only
- **The dashboard on a different host from your data.** Run the server with
  `RUSTRAK_DASHBOARD=off` and put `rustrak/rustrak-ui` (about 30 MB) on the
  other host. See
  [Dashboard on its own host](/configuration/production#dashboard-on-its-own-host)

## Telemetry

The server sends one anonymous report every six hours: version, platform and
health counters, never your data. Set `RUSTRAK_TELEMETRY=off` to turn it off.
[Telemetry](/configuration/telemetry) lists every field.

## First admin user

`CREATE_SUPERUSER` creates the first account on startup, in the format
`email:password`. It only does so when the database has no users yet; after
that it is ignored, so changing it does not change a password.

## Verify the installation

1. Open http://localhost:8080 (or your `PUBLIC_URL`) and sign in
2. You should see an empty project list

You're ready to [capture your first error](/getting-started/quickstart).
