The server uses mimalloc as its global allocator. glibc keeps one malloc arena per thread and never returns one once its thread exits, and the blocking pool retires threads on every burst, so resident memory climbed to the arena limit and stayed there: 700 MB at one event per second in production, 2 GB under a source-map-heavy burst. The same load now peaks around 520 MB and returns to 150 MB idle. Source maps are parsed once per event instead of once per frame, and the parsed form is kept across events in an LRU cache bounded by `SOURCEMAP_CACHE_MB` (default 64), keyed by file content so a re-upload never serves a stale parse. Concurrent misses on the same map wait for one load instead of repeating it, and a map larger than the whole budget logs a warning naming the variable to raise. The `debug_id` lookup still runs per event, so a deleted map stops resolving at once. A burst that took about five minutes to digest now takes under ten seconds. `docker-publish.yml` can be re-run for an existing tag through `workflow_dispatch`, skipping npm versions already on the registry, and builds the dashboard through turbo so `@rustrak/client` is compiled first.
